# FastScreen

[**Скачать FastScreen для Windows**](https://github.com/zhaunou/FastScreen/releases/latest) · [Состояние сборки](https://github.com/zhaunou/FastScreen/actions/workflows/build.yml)

Простая программа для Windows 10/11 x64. Скачайте ZIP из раздела Releases, полностью распакуйте его и запустите **FastScreen.exe**. Требуется .NET Framework 4.8; Python и инструменты разработки для использования не нужны.

Обычный запуск допускает только один экземпляр FastScreen для пользователя в текущем сеансе Windows. Повторный запуск возвращает работающее окно, включая скрытое в трее. Блокировка не зависит от имени или расположения EXE. Во время съёмки запрос открытия откладывается до её завершения; после сбоя блокировка не остаётся навсегда. Старые версии до 1.0.1 не поддерживают этот механизм — их нужно закрыть через меню трея.

## Версии

Номер хранится в одном файле `VERSION` в формате `MAJOR.MINOR.PATCH`. Например: `1.0.1` — исправление, `1.1.0` — новая возможность, `2.0.0` — несовместимые изменения. Для нового выпуска измените `VERSION`, дополните `CHANGELOG.md` и запустите сборку. Повторная сборка не увеличивает номер автоматически.

Сборка создаёт `FastScreen-<версия>.exe` и записывает этот же номер в свойства файла и интерфейс. В свойствах Windows версия файла имеет четыре части (`1.0.0.0`), версия продукта — три (`1.0.0`). Настройки и папка скриншотов общие для всех версий.

## Использование

При запуске появляется стартовый экран. Кнопка **Создать скриншот** открывает рабочий интерфейс; разделы **Создать скриншот** и **Горячие клавиши** доступны в верхней панели.

Интерфейс выполнен в светлой стилистике Windows 11: голубоватые поверхности, скруглённые карточки, синий акцент, подсветка наведения и клавиатурного фокуса. На Windows 11 системная рамка использует скругление и цвет заголовка; на Windows 10 остаётся стандартная рамка. Фон рисуется локально, без загрузки изображений из интернета.

- **Весь экран** — захватывает все подключённые мониторы одним изображением.
- **Выделить область** — зажмите левую кнопку мыши, выделите прямоугольник и отпустите. Esc или правая кнопка мыши отменяют съёмку.
- Снимок автоматически сохраняется в PNG. Окно программы скрывается перед захватом.
- Папка по умолчанию: `%LOCALAPPDATA%\LocalScreenshot\Screenshots`. Кнопка **Изменить…** позволяет выбрать другую папку, а **Открыть папку** показывает сохранённые снимки.
- **Открыть последний снимок** открывает PNG в стандартной программе просмотра.
- Глобальные сочетания по умолчанию: **Ctrl+Shift+F** — весь экран, **Ctrl+Shift+A** — область. Они работают из других программ и из трея, пока приложение запущено.
- В разделе **Горячие клавиши** выберите поле, нажмите своё сочетание и сохраните. Требуется Ctrl или Alt; можно добавить Shift. Для двух режимов нужны разные сочетания. Если сочетание занято, изменения не применятся. F12 зарезервирована Windows и не предлагается.
- **В трей**, сворачивание и крестик скрывают окно. Двойной щелчок по значку возвращает его. Меню значка позволяет сделать снимок или настроить клавиши. **Выйти** в меню полностью закрывает приложение и освобождает сочетания.
- Снимок из трея сохраняется без открытия основного окна; отмена выделения также оставляет программу в трее.

Программа не использует интернет, серверы, аккаунты или телеметрию. UNC-пути и сетевые диски не принимаются. Выбранная папка запоминается в `%LOCALAPPDATA%\LocalScreenshot\folder.txt`, горячие клавиши — в `hotkeys.txt` рядом с ним. Приложение не добавляет себя в автозагрузку.

Если Windows перенаправляет папку «Изображения» в OneDrive или другой сервис синхронизации, выберите обычную локальную папку: сторонний клиент может синхронизировать её содержимое независимо от программы.

Курсор мыши в снимок не включается. Защищённое видео и системный защищённый рабочий стол могут не захватываться.

## Сборка из исходников

Требуется .NET Framework 4.8 (входит в современные Windows), дополнительные пакеты не нужны.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

## Тесты отдельно от приложения

Пользовательский EXE не содержит тестовых классов и не поддерживает диагностические параметры. Для публикации нужен только `FastScreen-1.0.7.exe`.

Отдельная сборка тестов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\build-tests.ps1
.\obj\FastScreen.Tests.exe --logic
```

Режимы тестового EXE:

- `--headless`: проверки для CI без захвата рабочего стола и интерактивных окон; настройки, системные компоненты, курсор, звук и PNG из синтетического изображения.
- `--logic` (по умолчанию): настройки, загрузка системных компонентов, интерфейс, курсор, регистрация горячих клавиш и трей.
- `--render`: визуальные проверки трёх экранов, полей и курсора.
- `--full`: всё перечисленное, реальные снимки рабочего стола, PNG и сценарии захвата. Запускайте в обычном интерактивном сеансе Windows.

Каждый запуск создаёт новый каталог `%LOCALAPPDATA%\FastScreen\TestResults\<дата>-<случайный идентификатор>`. Произвольный путь отчёта через аргументы не принимается. Временные снимки удаляются после проверок; отчёт и превью интерфейса остаются в каталоге результатов. Не публикуйте личные диагностические изображения.

Дополнительные проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-single-instance.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-folder-guard.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\check-release.ps1 -Executable .\FastScreen-1.0.7.exe
```

Последняя команда проверяет отсутствие тестовых классов и старых диагностических параметров в релизе. `obj` и все EXE исключены из Git. Исходники релиза перечислены явно в `build.ps1`; тесты хранятся в `tests/` и собираются только по отдельной команде.

При выделении области используется крупное синее перекрестие с белой обводкой. Курсор не попадает в сохранённый снимок: изображение рабочего стола захватывается до начала выделения.

Восемь пробных звуков можно создать локально с Python 3: `python tools/generate-sounds.py`. WAV-файлы появятся в `obj/sound-previews`. Варианты 04 и 05 имеют мягкую атаку и повышенную на 3,5 дБ громкость относительно первых проб; 06–08 — дополнительные мягкие сигналы. В версии 1.0.3 подключён вариант 07 — мягкий колокольчик. Он звучит после успешного сохранения PNG, в том числе при съёмке из трея. При отмене выделения или ошибке записи звука нет. WAV встроен в EXE; сбой звука не мешает сохранению снимка. Для запуска самой программы Python не нужен.

В версии 1.0.4 системные DLL для собственных P/Invoke ищутся только в System32. Кнопка «Открыть папку» запускает Проводник по абсолютному пути из системной папки Windows, без поиска исполняемого файла через PATH.

Настройки читаются с ограничением размера: `folder.txt` — 4 КиБ, `hotkeys.txt` — 1 КиБ. Поддерживается UTF-8, включая BOM. Повреждённые, недоступные и слишком большие файлы дают настройки по умолчанию; исходные файлы при этом не перезаписываются. При сохранении используется уникальный временный файл в той же папке и атомарная замена. Неверные настройки не заменяют предыдущие; при ошибке записи программа показывает сообщение.

Папка сохранения проверяется при чтении настроек, выборе и непосредственно при записи. Принимаются обычные папки на локальных дисках; все reparse points (включая локальные ссылки, junction, точки монтирования и облачные placeholders) в компонентах пути отклоняются. На время записи проверенные каталоги удерживаются открытыми без разрешения переименования и изменения через другие дескрипторы. Если Windows не позволяет проверить путь, сохранение отклоняется. Проверка ссылок: `powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-folder-guard.ps1`.

FastScreen сам не загружает снимки в интернет. Однако сторонняя синхронизация обычной локальной папки (например, OneDrive) остаётся вне контроля программы.

## Автоматическая сборка и выпуски

GitHub Actions (`.github/workflows/build.yml`) запускает сборку на Windows Server 2022 при push в `main`, pull request и вручную через Run workflow. Проверяются headless-тесты, единственный экземпляр, обычные папки и junction, отсутствие тестов в пользовательском EXE и целостность ZIP. Реальное выделение области и захват рабочего стола проверяются локально через `--full`, а не на CI-сервере.

Для локального создания пакета:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

В `dist/` появятся архив `FastScreen-<версия>-windows.zip`, его `SHA256SUMS.txt` и `RELEASE_NOTES.md`. В ZIP входят FastScreen.exe, LICENSE, README.txt, SECURITY.md, CHANGELOG.md и контрольные суммы файлов. Существующий ZIP не перезаписывается: для повторной пробной сборки используйте новый `-OutputDirectory`.

Для нового релиза измените `VERSION` и `CHANGELOG.md`, отправьте проверенный коммит в `main`, затем создайте и отправьте тег `v<версия>`. Тег должен точно соответствовать `VERSION`. Только push тега запускает публикацию: после успешных проверок создаётся черновик Release с пакетом и контрольной суммой, затем он публикуется. Обычные push, pull request и ручные сборки Release не создают. Существующий выпуск автоматически не заменяется.

Для GitHub Actions используются закреплённые SHA официальных actions; у сборки есть только права чтения, права записи выдаются отдельной задаче публикации. Личные токены в настройках репозитория не требуются — используется временный GITHUB_TOKEN. EXE пока не подписан цифровой подписью.
